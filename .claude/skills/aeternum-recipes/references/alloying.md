# Alloying methods

To add an alloy everywhere, cover every row. Worked example: `groovy/postInit/mods/projectred.groovy` (Red Alloy / Electrotine Alloy loop, and the Doped Silicon loop) + `scripts/mods/projectred.zs` (NuclearCraft part).

| Machine | Language | API | Notes |
|---|---|---|---|
| IE Alloy Kiln | Groovy | `mods.immersiveengineering.alloy_kiln.recipeBuilder().input(a, b).output(x).time(200)` | Exactly 2 inputs, counts allowed (`ore('dustRedstone') * 4`). IE's own ore-dict alloys add both `ingot` and `dust` base variants. |
| IE Arc Furnace | Groovy | `mods.immersiveengineering.arc_furnace.recipeBuilder().mainInput(a).input(additives...).output(x).time(100).energyPerTick(512).alloying()` | `.alloying()` sets IE's "Alloying" recipe type (what IE uses for its own alloys); `.slag(stack)` optional. |
| Ender IO Alloy Smelter | Groovy | `mods.enderio.alloy_smelter.recipeBuilder().input(a, b, c).output(x).energy(2000).tierAny()` | Up to 3 inputs; tier `tierSimple/Normal/Enhanced/Any`. |
| Thermal Induction Smelter | Groovy | `mods.thermalexpansion.smelter.recipeBuilder().input(a, b).output(x).energy(4000)` | 2 inputs; default energy 4000. Registers one recipe per matching-stack pair of an ore input. |
| Mekanism Metallurgic Infuser | Groovy | `mods.mekanism.metallurgic_infuser.recipeBuilder().input(a).infuse('REDSTONE').amount(40).output(x)` | 1 item + an infuse type (upper-case name, e.g. `REDSTONE`, `CARBON`, `ELECTROTINE`, `GLOWSTONE`); 1 Redstone dust = 10 infuse. Add a source item with `mods.mekanism.infusion.add('TYPE', amount, ingredient)`. |
| NuclearCraft Alloy Furnace | CraftTweaker | `mods.nuclearcraft.AlloyFurnace.addRecipe(in1, in2, out, timeMult, powerMult, radiation)` | No GroovyScript compat. Ore-dict inputs work here (the ore-dict bug is Manufactory-only). |
| Rockhounding Metal Alloyer | CraftTweaker | `mods.rockhounding_chemistry.MetalAlloyer.add(["dustA", "dustB"], [80, 20], <out>)` | Percentage-based dust compositions; not used for ProjectRed alloys (user's call). |
| Tinkers' Smeltery | Groovy | `mods.tconstruct.alloying` | Fluid-only: needs a molten fluid for each input and the output, so it can't make alloys with no fluid (e.g. Red Alloy). |
| Vanilla furnace | Groovy | `furnace.recipeBuilder()` | ProjectRed's own route: Red Iron Compound (Iron Ingot + 8 Redstone) and Electrotine Iron Compound (Iron Ingot + 8 Electrotine) smelt into the alloys. |

Doped Silicon (Infused/Energized/Electrotine Silicon = Silicon `projectred-core:resource_item:301` + 8 Redstone/Glowstone/Electrotine dust, outputs meta 320/341/342) is a second worked example, 1 base item + 8 dust. It is in every row above except Tinkers' and Rockhounding: Alloy Kiln, Arc Furnace, Alloy Smelter and Induction Smelter take `silicon` + `ore(dust) * 8`, the Metallurgic Infuser uses 80 infuse (8 dusts), NuclearCraft is in `scripts/mods/projectred.zs`.

No other item alloyer is installed: Embers' Mixer Centrifuge mixes fluids only, and IC2 Experimental has no alloy smelter.

## New Mekanism infuse types

Don't use `mods.mekanism.infusion.addType()`: it calls `Minecraft.getMinecraft()` and crashes the dedicated server. Register with `InfuseRegistry.registerInfuseType(new InfuseType(...))` in `groovy/preInit/mekanism.groovy` (Mekanism's stitch handler sets the icon) and add an `infuse.<name>` lang key in `groovy/assets/aeternum/lang/en_us.lang`.

**`groovy/sideOnly.json` is required for this to boot on the dedicated server.** `InfuseType` has a client-only `TextureAtlasSprite` field `sprite` and `setIcon(TextureAtlasSprite)`, so GroovyScript (1.4.3) can't reflect the class on a server. `JavaBeanException` then logs "Found N failing members. GroovyScript will add these to sideOnlyGenerated.json" and writes **every** member it can't fetch via `getDeclaredField`/`getDeclaredMethod`, which here was all of `InfuseType` including `name`. On the next boot `GroovyScriptTransformer.transformSideOnly` strips those members (the `client` section = removed on the server) and Mekanism's own preInit dies with `NoSuchFieldError: java.lang.String name`. The fix is the hand-written `groovy/sideOnly.json`, which lists only the real client-only members (`"client": {"mekanism.api.infuse.InfuseType": ["sprite", "setIcon()"]}`). Add an entry there for any other class Groovy scripts touch that has client-only members.
- **Symptom and cleanup:** a "failing members" message on a server means that server's `groovy/sideOnlyGenerated.json` is poisoned. Remove the bad entries from it (the server keeps its own copy; the tracked one in the repo is clean) and declare the real client-only members in `groovy/sideOnly.json`.
Match Mekanism's own source values so a new type feels like the built-in ones. Redstone: dust 10, Compressed Redstone 80 (Enrichment Chamber, 1 dust -> 1), block 90; Carbon: coal 10, charcoal 20, Compressed Carbon 80, coal block 90 (`mekanism.common.Mekanism`, `registerInfuseObject` calls). The `ELECTROTINE` type follows Redstone: Electrotine Dust 10, `aeternum:compressed_electrotine` 80 (made from 1 dust in the Enrichment Chamber), `blockElectrotine` 90, all in `groovy/postInit/mods/projectred.groovy`. Its icon is `groovy/assets/aeternum/textures/blocks/infuse/electrotine.png`, Mekanism's `infuse/redstone.png` hue-shifted to Electrotine blue (#0e73aa); the compressed item's texture is `compressedredstone.png` shifted the same way. The `GLOWSTONE` type follows the same pattern (used by Energized Silicon): `ore('dustGlowstone')` 10, `aeternum:compressed_glowstone` 80 (Enrichment Chamber, 1 dust -> 1), vanilla Glowstone block 40 (it is only 4 dust, so not 90), also in `projectred.groovy`. Its icon `textures/blocks/infuse/glowstone.png` and `textures/items/compressed_glowstone.png` are the same Mekanism Redstone textures recoloured to Glowstone gold (hue 42°, saturation scaled to 0.78 average, value lifted with `1-(1-v)*k` toward 0.86 so highlights keep contrast).
